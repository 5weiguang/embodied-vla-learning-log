## 实际验证了什么？

本轮学习对话中，助手使用本机 Python/NumPy 计算 8 步一维动作的 DCT、量化和重建，并在 16 条构造序列上演示整数符号 BPE。归档时将这个例子整理为脚本、重新运行并保存 JSON；JSON 的环境信息对应归档重跑，不伪装成对话初次执行的原始日志。

脚本使用显式正交 DCT-II 矩阵，没有调用官方 FAST+ 处理器。合成动作由指定系数经逆 DCT 构造，不包含真实机器人数据、训练数据归一化拟合、多维展开或视觉输入。

## 重新运行

需要 Python 与 NumPy；不需要 GPU、模型权重或机器人环境。从仓库根目录运行：

```powershell
python experiments/FAST/tokenizer_demo.py
```

上面的命令只计算并打印，不覆盖归档。保存自己的结果时，使用新的文件名，例如：

```powershell
python experiments/FAST/tokenizer_demo.py --output experiments/FAST/results/my_rerun.json
```

脚本中的 record_date 标注此教学例子的归档日期；自己的复现实验应在说明中另记实际日期、执行人和环境，不把此固定字段当作实时运行时间。

## 归档结果

| γ | 零系数数目 | 动作 MSE |
|---:|---:|---:|
| 2 | 6 | 0.0085 |
| 10 | 4 | 0.00025 |
| 100 | 4 | 0 |

DCT 正逆变换最大误差约 10⁻¹⁵。γ=100 的零误差由人为选择的系数恰好落在量化网格上造成，不代表真实动作可以无损量化。

BPE 的四次合并使目标长度从 8→6→5→4→3；展开后与原整数序列完全一致，γ=10 的动作 MSE 仍约 0.00025。脚本检查矩阵正交性、DCT 正逆变换、整数精确还原以及 BPE 前后误差一致。

**证据范围：** 学习 BPE 的 16 条序列刻意共享后缀，目标例子就在其中，没有保留测试集。该结果只验证此教学构造，不能支持真实机器人上的压缩比、泛化、模型学习改善或推理速度。
